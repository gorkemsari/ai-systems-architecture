## 📖 About This Handbook

This repository is the source of an in-depth digital handbook on **the architecture of AI systems**: integrating LLM-based capabilities into production systems so that they are secure, scalable, observable, and cost-effective. It is written for solution and software architects and senior engineers who already build distributed systems and now have to make them work with a component that is probabilistic by nature.

It treats AI as an architectural concern rather than a modeling one. The handbook covers model strategy and routing, context engineering, retrieval and knowledge architecture, tool use and agents, evaluation as an engineering discipline, AI security, reliability patterns, inference serving on Kubernetes, AI gateways and internal platforms, LLMOps, cost economics, data governance, and regulation (including the EU AI Act, KVKK, and BDDK), closing with pattern catalogs and reference architectures. Model training and ML mathematics are out of scope.

It is the companion of the [Distributed Systems Handbook](https://github.com/gorkemsari/distributed-systems). Primitives such as idempotency, sagas, backpressure, caching, and consistency models are explained there once; pages here apply them to AI systems and link to the canonical page instead of repeating it.

## ✍️ How This Handbook Is Written

Pages are drafted by an AI model (Claude, by Anthropic) through a scheduled pipeline that publishes one page at a time, in English and Turkish. The author defines the scope, structure, and writing standards and maintains the pipeline; the specification every page must follow is [`authoring/project-instruction.md`](authoring/project-instruction.md).

Before a page is published it must pass automated checks: structure and length rules, valid cross-references (including links into the Distributed Systems Handbook), matching English and Turkish structure, a full site build, and rendering of every diagram. Version-specific facts are checked against current sources while drafting, and illustrative numbers are labeled as illustrative. Pages are published without manual review and may be revised later, so errors are possible: if you find one, please [open an issue](https://github.com/gorkemsari/ai-systems-architecture/issues).

The pipeline itself, including the generation queue and the run log, lives in [`authoring/`](authoring/).

## 🛠️ Tech Stack & Local Development

The site is built with [Astro](https://astro.build/) and [Starlight](https://starlight.astro.build/), with diagrams written in [Mermaid](https://mermaid.js.org/). Every push to `main` builds the site and deploys it to GitHub Pages through GitHub Actions.

### Prerequisites
- Node.js 22 or newer
- [pnpm](https://pnpm.io/)

### Running Locally

1. **Clone the repository**
   ```bash
   git clone https://github.com/gorkemsari/ai-systems-architecture.git
   cd ai-systems-architecture
   ```

2. **Install dependencies**
   ```bash
   pnpm install
   ```

3. **Start the development server**
   ```bash
   pnpm dev
   ```
   The site will be available at `http://localhost:4321/ai-systems-architecture/`.

### Production Build

```bash
pnpm build      # output in dist/
pnpm preview    # serve the built site locally
```

In production, Mermaid diagrams are rendered to inline SVG at build time, so readers download no diagram JavaScript. Local builds render diagrams in the browser instead. To reproduce the production output, install Chromium once and build with `MERMAID_SSR=1`:

```bash
pnpm exec playwright install chromium
MERMAID_SSR=1 pnpm build
```
